# Sidebar navigation and landing page polish for ApexFunded

This change adds a persistent sidebar layout to the Dashboard and Admin pages and dials back the visual intensity of the landing page for a more professional feel. The sidebar introduces a DashboardLayout wrapper that handles fixed-position desktop navigation and an animated mobile drawer. The landing page refinements reduce glow blob sizes and opacities, tighten typography, shrink scrollbar styling, and add subtle hover-glow effects across Features, Stats, and Footer components.

**Watch for:** Sidebar navigation links are non-functional stubs — all point to `/dashboard` (confirmed). The `profileName` prop is accepted by DashboardLayout but never used (confirmed). Mobile sidebar close button overlaps the Sidebar logo region (likely).

## High-level view

The sidebar is split into two components: `Sidebar.tsx` (the nav list) and `DashboardLayout.tsx` (the responsive shell with mobile drawer). Both Dashboard and Admin pages wrap their existing content with `<DashboardLayout>`, removing the old "Back to site" link in favor of the sidebar's Home link.

The navigation links all route to `/dashboard` regardless of label (Accounts, Trades, Payouts). This makes the sidebar visually complete but functionally a placeholder. The `isActive` logic can never highlight any item except "Overview" since it requires both `pathname === "/dashboard"` and `label === "Overview"`.

The landing page changes are purely cosmetic: global glow opacity from 0.55 to 0.30, body radial gradient opacities halved, hero blobs downsized with explicit `opacity-25` on top of the base 0.30, and Feature card hover reduced with a new glow shadow. No behavioral or routing changes touch the landing page.

## Sidebar navigation: placeholder hrefs and dead active logic

The `mainLinks` array defines five entries — Overview, Accounts, Trades, Payouts, Settings — but all four non-Settings items have `href: "/dashboard"`. There are no matching routes for `/dashboard/accounts`, `/dashboard/trades`, etc. Clicking Accounts or Trades does nothing the user can perceive.

The `isActive` function compounds this:

```tsx
function isActive(item: NavItem) {
  if (item.href === "/admin") return pathname === "/admin";
  if (item.href === "/dashboard") return pathname === "/dashboard";
  return false;
}
```

Every main link satisfies `item.href === "/dashboard"`, but the active highlight is further gated:

```tsx
const active = isActive(item) && item.label === "Overview" && pathname === "/dashboard";
```

If future sub-routes are added, `isActive` would need prefix matching rather than equality, and the label check would need to be removed. The current logic is dead code for any item other than Overview.

On the Admin page, `onSettingsClick` is not passed to DashboardLayout, so clicking Settings in the admin sidebar fires nothing — the optional chaining makes it a silent no-op rather than a crash, but it's still a dead button.

## DashboardLayout: unused prop and mobile overlap

`DashboardLayout` accepts `profileName?: string` but never renders it anywhere — not in the sidebar, not in the mobile top bar. The Dashboard page passes `profile?.full_name ?? undefined`, so there's a data path that goes nowhere.

The mobile close button is positioned `absolute right-3 top-5` inside the mobile drawer. The Sidebar component's logo sits at `py-6` in the same 256px-wide container. The X button lands directly adjacent to or overlapping the logo mark. It should be pushed further right or positioned outside the Sidebar's bounding box to avoid visual collision.

## Landing page: double opacity stacking and unused utility

The global `.glow-blob` class sets `opacity: 0.30` in `globals.css`, but Hero.tsx also applies `opacity-25` as a Tailwind class on each blob element. These multiply: the hero blobs render at approximately 7.5% effective opacity, which may be more aggressive than intended. If the intent was 25% opacity on the hero blobs specifically, the global 0.30 should be overridden rather than stacked.

`tracking-tight-2` is defined in `tailwind.config.ts` but not applied anywhere in this changeset. If it's prep for a future pass, that's fine; if it was meant to be used on the hero heading, it's missing.
